## 1. Decisão e ADR

**Editor: VSCodium com a extensão oficial `Anthropic.claude-code` do Open VSX, presa à versão do CLI. Terminal: kitty.** O porquê está no ADR; aqui fica o que decide.

Duas restrições separam os candidatos: **(a)** as sessões `claude` do tmux (`ai-pane`) se ligam ao editor por `/ide`; **(b)** o editor honra `~/.claude/settings.json` e `/opt/wiki/.claude/settings.json` (hooks, `model: fable`, MCP, roster). A extensão **é** o Claude Code, então cumpre as duas. O Zed com o adaptador ACP cumpre (b) — a refutação 1 do plano provou `settingSources: ["user","project","local"]`, hooks, CLAUDE.md, MCP e plan mode no código do adaptador — e não cumpre (a): não há ponte `/ide` para um CLI em terminal externo. Por isso o Zed é **fallback atrás de gate**, não principal.

Rubrica do plano §5.2 (0–10, ponderada): VSCodium 9,2 · Zed 8,3 · VS Code da Microsoft 8,25 · Neovim 7,95. O total não decide; decide que só o VSCodium e o VS Code da Microsoft cumprem (a), e o segundo está vetado pelo dono.

**Livre é o editor.** O VSCodium é build MIT do VS Code, sem telemetria. A extensão e o CLI são proprietários — "All rights reserved" — e o `legal-and-compliance.md` da Anthropic só exige que o binário do Claude Code não seja modificado. A primeira redação do plano chamava tudo de livre; a refutação 1 corrigiu.

**Gate de fallback (plano §5.4), pré-registrado:** (1) `codium --install-extension anthropic.claude-code@<versão>` instala a mesma versão de `claude --version`; (2) com o editor em `DISPLAY=:99` sobre `/opt/wiki`, um `claude` no tmux conecta por `/ide`, com um lock e com dois; (3) o painel responde sem tela de login, reaproveitando `~/.claude/.credentials.json`, e um `/plan` abre o Markdown no editor. Qualquer prova falhando por defeito do VSCodium ou do Open VSX — não por configuração corrigível em até duas tentativas — troca o principal para Zed + `@agentclientprotocol/claude-agent-acp` (canal `latest`) na mesma sessão, com o ADR atualizado. Resultado das três provas: §8.
